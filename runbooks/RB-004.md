# Runbook: checkout-api — Memory / OOM

## Symptoms

checkout-api containers restart with exit code 137. `kubectl describe pod`
reports `OOMKilled`. Memory working set climbs steadily between restarts rather
than holding flat — a sawtooth on the Grafana board. The
`checkout-api-restarts` alert fires. Request latency on `/cart` and `/checkout`
climbs in the minutes before each restart as garbage collection pressure builds.

## First checks

1. Check the deploy log for a recent release. `kubectl rollout history deploy/checkout-api`.
   The large majority of memory incidents on this service follow a deploy within the previous hour.
2. Open the checkout-api Grafana board and compare memory against request rate. If memory
   has risen while request rate has stayed flat, the cause is the code, not the traffic.
3. Check whether the container memory limit was changed recently. A limit lowered
   below the real working set presents as a sudden onset of OOM kills with no code change.
4. Check cart sizes. A small number of very large carts — bulk orders, or a
   scripted client — will blow the per-request memory budget.

## Diagnosis

Take a heap snapshot from a pod that has been running for a while:

```
kubectl exec -it <pod> -- py-spy dump --pid 1
kubectl exec -it <pod> -- python -c "import tracemalloc, gc; ..."
```

Look for retained cart objects, an unbounded in-process cache, or accumulated
session data. Those three account for most memory regressions we have seen in
this service.

## Mitigation

If a deploy correlates, roll it back — see the rollback runbook. Rollback is
preferred over raising the memory limit, because raising the limit on a leak
only lengthens the interval between restarts.

If a specific cache is implicated, clear it and set a bound.

If neither correlates and the working set is genuinely larger, raise the
container memory limit and open a capacity ticket.

## Escalation

If OOM kills continue fifteen minutes after mitigation, escalate to the
Checkout team's secondary on-call. See the escalation policy for the paging
chain and the timings.
