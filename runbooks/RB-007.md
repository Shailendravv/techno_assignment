# Runbook: inventory-api — Too many connections

## Symptoms

inventory-api logs fill with `FATAL: sorry, too many clients already` or
`remaining connection slots are reserved`. Application logs show
`QueuePool limit of size 20 overflow 10 reached, connection timed out`.
Requests to `/stock` return 500 while `/health` continues to pass, because the
health check does not take a database connection. The
`inventory-api-5xx-rate` alert fires.

## Likely cause

Connection pool exhaustion against the inventory Postgres primary. In every
incident we have recorded, the cause has been one of three things:

1. **A deploy that raised replica count without lowering per-pod pool size.**
   Total connections are `replicas x pool_size`.
2. **A slow query holding connections open.** Stock reconciliation queries scan
   wide date ranges and are the usual offender on this service.
3. **A connection leak** — a code path that takes a connection and does not
   return it, usually an error path that skips the context manager.

## First checks

1. Count current connections in `pg_stat_activity`, grouped by state. A large
   `idle in transaction` count points at a leak. A large `active` count points
   at slow queries.
2. Check the deploy log. `kubectl rollout history deploy/inventory-api`.
   Correlate against the replica count at the time.
3. Check whether a stock sync job is running. Sync holds connections for the
   length of the batch and overlaps badly with peak read traffic.

## Mitigation

If a deploy correlates, roll it back.

If a single slow query is holding connections, terminate its backend process.
Do this before scaling anything.

If a sync job is implicated, pause it. Sync is resumable and will catch up.

Do **not** raise `max_connections` on the primary as a first response. It moves
the failure from the pool to the database's memory, which fails harder and
recovers more slowly.

## Escalation

If connections are not recovering fifteen minutes after mitigation, escalate to
the Inventory team's secondary on-call. See the escalation policy.
